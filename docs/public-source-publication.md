# 공개 소스 기준과 검증 범위

## 출처와 모듈화 방식

- 기준 스냅샷: `1732a1c33794716ec8de08611f4f569105b1a5ba`
- 애플리케이션 버전: `0.8.11` 후보
- 공개 저장소: `charater1024-lang/bora-brdige-project`
- 기존 저장소의 Git 이력을 가져오지 않고, 검사한 커밋의 추적 파일만 새 저장소에 복사했습니다.
- 웹·API·도메인 로직·RAG·공공정보·DB 구조·Local LLM·운영 도구의 폴더와 import 경로를 유지하고, 모듈별 책임·설정·검사 문서를 보강했습니다. 실행 코드의 동작을 바꾸는 리팩토링은 포함하지 않습니다.
- 원본의 긴 기능 설명은 루트 `SOURCE-README.md`에 보관하며, 오래된 조회/설치 안내를 정정했습니다. 고정된 평가 manifest에 포함된 문서와 합성 데이터는 변경하지 않았습니다.

## 포함하는 것

애플리케이션·수집기·게이트웨이 소스, 의존성 잠금파일, DB 스키마와 마이그레이션, 합성 테스트·평가 자료, 빈 비밀값의 환경 예시, 범용 배포 템플릿, 브랜드 이미지, 공개 소개자료를 포함합니다.

## 포함하지 않는 것

실제 API/OAuth 키·인증 토큰·관리자 고유 신원·개인 연락처, 실제 회원·자산·세션 DB, 수집된 운영 데이터, 운영 환경 파일·설치된 서비스 설정·터널 자격증명, 로그·백업·모델 가중치·의존성 설치물·빌드 산출물은 포함하지 않습니다. `.gitignore`만 믿지 않고 게시할 Git 객체도 검사합니다.

예제의 `borabridge.com`, 공개 API 주소, 루프백 주소와 모델 식별자는 비밀정보가 아닙니다. 새 설치에서는 자신의 환경에 맞게 설정해야 하며 원래 운영 서비스의 이용 권한을 제공하지 않습니다.

### 해결 전 의존성 보안 경고

2026-09-27의 `npm audit --omit=dev` 결과는 **critical 1개, high 1개, moderate 1개**입니다. 따라서 이 스냅샷을 의존성 보안 검사가 완료된 운영 배포본으로 취급해서는 안 됩니다. 이 경고는 비밀키가 발견되었다는 뜻이 아닙니다.

- Next.js 16.2.12: Windows 서버 요청 처리 및 이미지 최적화 관련 권고. [Next.js 권고 1](https://github.com/advisories/GHSA-p293-qw3h-jr36), [Next.js 권고 2](https://github.com/advisories/GHSA-2xp9-vwfh-vxw4)
- sharp 0.35.3: 포함된 이미지 처리 라이브러리의 취약점 경고. [sharp 권고](https://github.com/advisories/GHSA-rgj7-g3m4-5g8c)
- baseline-browser-mapping: 입력 처리 중 프로세스 종료 관련 경고. [권고](https://github.com/advisories/GHSA-w5vr-8v7q-w6rv)

앱은 기본 스크립트에서 `next start`가 아닌 vinext/Worker 경로를 사용합니다. 실제 공격 가능성은 플랫폼·사용 API·이미지 처리 경로에 따라 달라지며, 이번 소스 공개 점검으로 운영 서버의 노출 여부를 확정하지 않았습니다. 이 공개본은 기준 스냅샷의 실행 코드와 의존성을 보존하고 알려진 경고를 명시하는 기록용 게시입니다. 라이브러리 보안 패치는 포함하지 않으며, 기존 v17 평가 봉인도 소급 변경하지 않습니다. 실제 운영에 사용하기 전에는 패치된 의존성으로 별도 재검증해야 합니다.

이전 기록에서 확인된 운영판은 v0.8.10입니다. v0.8.11 후보의 24시간 검사는 워밍업 중 안전 중단되어 미통과했습니다. 이 공개 작업은 운영 서버 변경·배포·재부팅·DB migration을 수행하지 않습니다. 실제 네이버/카카오 로그인, 제공기관 API 승인, Local AI 실추론, 회원 데이터 일치와 장기 부하는 별도의 통합 환경에서 검증해야 합니다.

기존 평가 세트는 오프라인 합성 사례입니다. 과거 봉인·점수·소스 해시는 보존하며 현재 운영 성능이나 실제 AI 답변 정확도로 바꾸어 표현하지 않습니다.

### 데이터·암호화의 별도 한계

API 키 암호화와 세션 토큰 해시 저장은 확인했으나 자산·프로필을 포함한 DB 전체 암호화는 아닙니다. Windows 백업 도구의 기존 명시적 폴더 권한 검증 누락과, 백업 도구 직접 실행 시 평문 백업이 가능한 경로도 기록했습니다. 실제 운영 설정 및 노출 여부는 검사하지 않았으며 해당 도구를 실제 데이터에 사용하기 전 보완·검증이 필요합니다. [구현 근거·미해결 사항·운영 확인 범위](data-security-boundaries.md)를 참고하세요.

## 공개 후 실수 방지

```bash
npm run hooks:install
npm run check:public-source
npm run check:public-source:head
npm run check:public-source:history
```

커밋 훅 설치는 해당 로컬 저장소 설정을 바꾸므로 설치 전에 안내를 확인합니다. GitHub의 보안 검사는 읽기 전용이며 배포와 비밀정보 접근을 하지 않습니다. 전체 평가 workflow는 새 저장소의 `main` PR과 수동 실행을 대상으로 합니다. 정규식 검사는 모든 비밀정보·개인정보를 보장하지 않으므로 문서·이미지도 검토해야 합니다.
