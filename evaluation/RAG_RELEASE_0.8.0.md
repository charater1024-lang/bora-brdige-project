# RAG v0.8.0 구현·검증 기록

## 범위

기존 원격 서버, D1/SQLite 공개자료 저장소, 단일 Local AI 운영 구조를 유지한다. 마이데이터 연결, 모델 교체·다운로드, 벡터 DB 도입, 추가 유료 API 호출은 포함하지 않는다.

1. 전체 저장 공개자료의 FTS5 검색과 구조화 필터
2. 동의한 이전 질문을 이용한 후속 질문 처리
3. 질문 관련 법령 발췌와 실제 전달 자료의 인용·수치 경계
4. 접힌 근거 UX와 재실행 가능한 평가

## 데이터·운영 설계

- `drizzle/0023_public_rag_index.sql`은 `public_data_catalog_chunks`의 공개 필드만 검색용으로 투영한다. 사용자 정보, API 키, 대화 내용, 상권 경계 geometry는 색인하지 않는다.
- 처음 한 번 전체 자료를 색인한다. 이후 원천 chunk의 추가·교체·수정·삭제 시 해당 부분만 동기화한다. 상담 요청은 FTS 후보 최대 64개를 조회하고 의미 있는 검색어·지역·만료 조건으로 재정렬한다.
- 현재 방식은 BM25·다국어 표현 확장·구조화 필터다. 임베딩 기반 의미 검색을 구현한 것으로 설명하지 않는다. 실제 API가 제공하지 않은 신청조건·지역자격을 보충 생성하지 않는다.
- KOSAF 캐시의 `nationwide`는 기존 어댑터 기본값이므로 RAG에서는 실제 신청자격의 증거로 인정하지 않는다. 지역 조건을 미확인으로 두고 명시 지역 검색에서는 제외한다. 제공기관 이름만으로 거주자격을 추측하지 않는다.
- Local AI 입력은 4,096 토큰 문맥을 기준으로 보수적으로 예산화한다. 최대 4개 근거를 온전한 블록으로 넣고, 조건부 문장을 잘라서 맞추지 않는다. 남은 공간에만 동의한 개인 배경·대화가 들어간다.
- 근거는 낮은 신뢰도의 참고 데이터로 최종 질문 가까이에 배치한다. 모델용 `[S1]` 등의 짧은 번호는 서버가 이번 요청에 실제 넣은 출처 ID로만 복원한다.
- 대화 활용은 Local 모델·계정에 저장된 동의·해당 요청의 동의가 모두 필요하다. 수동 장부도 기존 별도 저장 동의를 유지한다. 사용자 정보를 공용 색인이나 법령 공용 캐시에 넣지 않는다.
- 질문에 필요한 자료가 없거나 색인이 이용 불가이면 모델 호출 전에 구분 안내한다. 법령은 현행 공식 근거가 없으면 답변하지 않는다.

## 검증 방법과 관찰

다음 명령은 외부 모델 호출 없이 재실행할 수 있다.

```bash
npm run test:rag
npm run eval:rag
```

평가 자료는 99개 합성 개발 진단 사례다. 고정된 이전 검색 구현과 비교하며 기존 sealed 대회 평가 자료는 수정하지 않았다. 실패 사례를 개발 중 확인한 뒤 개선했으므로 독립 held-out 인증이나 운영 정답률로 사용하지 않는다.

2026-08-30 검증 시점의 검색 진단에서는 고정 안내문 Recall@5가 53.7%에서 70.7%, MRR@5가 0.524에서 0.683으로 변했다. 오검색은 10개 음성 사례 중 3건에서 2건으로 줄었으며 잔여 실패를 보고서에서 제거하지 않는다.

운영 DB를 읽기 전용으로 열고 공개자료만 메모리 임시 DB로 옮긴 서버 검증에서는 331개 저장 chunk, 총 30,404개 공개 레코드를 색인했다. 5개 질문의 검색은 약 9~24ms, 임시 색인 생성은 약 1.6초였다. 이는 제한된 검증 표본의 검색 시간이지 API 전체 지연이나 동시접속 성능을 뜻하지 않는다. 해당 진단 프로세스의 최대 RSS 약 260MB도 운영 앱의 추가 메모리와 동일한 수치가 아니다.

기존 EXAONE 4.0 1.2B Q4 모델에 합성 질문 3개를 보내 실측했다. system에만 근거를 넣은 첫 방식은 무인용·근거 외 수치 답변을 만들었다. 질문 가까이에 근거를 두고 짧은 출처 번호를 쓰는 방식으로 바꾼 재검사에서는 3개 답변의 인용·수치 경계가 통과했으며 약 1.7~3.0초가 걸렸다. 같은 소수 질문으로 조정한 결과이므로 전체 질문의 정확도나 의미적 근거 일치가 입증된 것은 아니다.

## 남는 한계

- 출처 ID, URL, 금액·금리·날짜 검사는 의미적 함의 검증이 아니다. 숫자가 없는 잘못된 설명이나 정확한 수치를 잘못된 의미로 쓰는 경우까지 전부 판별하지 못한다.
- 사용자 입력 장부를 활용하는 개인 계산에는 공식 수치 검사 예외가 있으며 응답 메타데이터를 `citation-only-checks-passed`로 구분한다. 실제 공공 자료가 함께 쓰이면 수치 검사를 다시 적용한다.
- 확인 날짜가 접수 마감으로 잘못 쓰이지 않도록 메타데이터 날짜는 수치 근거로 무차별 합치지 않는다. 따라서 확인일을 서술한 정상 답변도 보수적으로 발췌 안내로 대체될 수 있다.
- 큰 법령 항 전체가 문맥 한도를 넘으면 생략을 명시한다. 원문 전체나 모든 예외를 읽은 것처럼 표현하지 않는다.
- 수집된 자료 범위·원천의 설명 충실도에 검색 품질이 제한된다. 마감 미제공은 모집 중이라는 뜻이 아니고, 지도/분류 지역도 최종 신청자격을 확정하지 않는다.
- 다음 단계의 의미 검색·재정렬 모델 도입은 별도의 비공개 평가셋, 실제 답변의 사람 검토, 동시접속·지연·메모리 측정 후 판단한다.

## 배포 원칙

운영 소스와 DB를 백업하고 분리된 폴더에서 빌드한 뒤 적용한다. 실패하면 이전 소스·빌드와 타이머 상태를 복구한다. 새 색인은 기존 코드와 호환되는 추가 구조이며, 운영 DB 전체를 예전 사본으로 덮어써 배포 이후 회원 데이터를 잃게 하는 롤백은 하지 않는다.
