# BORA RAG 합성 진단셋 v1

이 파일명에 `benchmark`가 있지만, **독립 benchmark나 held-out 성능 인증이 아니다.** 구현과 제품 범위를 알고 있는 코딩 에이전트가 만든 합성 진단셋이다. 사람의 정답 검수와 실제 사용자 분포 검증은 수행하지 않았다. 첫 실행 후 실패 사례를 구현 담당자에게 공유했으므로 이후의 개선 수치는 공개된 개발·회귀 질문에 대한 결과다. 질문을 통과시키기 위해 정답 라벨을 바꾸지 않는다.

기존 sealed judge core/coverage, 기대값, 점수에는 영향을 주지 않는다. 종합 100점이나 실사용 정확도로 환산하지 않는다.

## 구성

| 검사 | 건수 | 확인하는 것 |
| --- | ---: | --- |
| 고정 지식 검색 | 51 | 자연어·다국어·코퍼스 없는 주제·현재 상세값이 없는 일반 안내 |
| 후속 질문과 주제 전환 | 8 | 명시 전달된 이전 질문 연결, 새 주제 분리, 모호한 질문 확인 |
| 고용통계 의도 | 16 | 통계 요청과 취업·서류·면접 요청 구분 |
| 인용 경계 | 12 | 알려진 ID, URL, 주요 금액·비율·날짜 및 기계 채점하지 않는 의미 불일치 예시 1개 |
| 공개자료 검색 | 12 | 합성 문서의 관련성·지역·마감·잘못된 URL |
| 합계 | 99 | 네트워크·모델 호출 없이 실행 |

고정 지식 검색 중 2개는 기존 core 사례를 감사에서 재생한 `audit-regression-existing-core`다. 나머지는 `new-synthetic-diagnostic`이며, 두 그룹의 지표를 JSON에서 구분한다. 한·영·일·중 언어별 지표도 별도로 제공한다.

`corpusStatus`의 의미:

- `guidance-available`: 질문에 관련된 일반 안내문이 있다.
- `detail-unavailable`: 일반 확인 원칙은 있으나 질문의 최신 금리·모집상태·개별 자격 등을 확정할 자료는 없다. 검색 성공을 완전한 답변 가능으로 해석하지 않는다.
- `topic-unavailable`: 이 코퍼스에는 관련 근거가 없다고 합성 라벨을 붙였다. 오검색 여부를 확인한다.

공개자료의 제목·금액·통계·기한은 모두 합성이며 실제 공고나 KOSIS 실측치가 아니다. URL은 예약된 `.example` 도메인을 사용하며, 거부용 unsafe URL 하나는 문자열로만 처리한다. 실제 계정·개인정보·운영 DB를 조회하지 않는다.

## 실행

```sh
node scripts/evaluate-rag.mjs
node scripts/evaluate-rag.mjs --json
node --test tests/rag-evaluation.test.mjs
```

요약은 지표만, `--json`은 각 질문의 검색 ID와 실패 이유까지 출력한다. 결과 파일을 자동 생성하거나 서버 상태를 바꾸지 않는다. 잘못된 fixture/호출 계약은 오류로 종료하지만, 모든 자연어 질문을 통과해야 실행이 성공하는 방식은 아니다. 낮은 검색 지표와 잔여 실패도 그대로 출력한다.

기본 경로는 모델·외부 API를 호출하지 않는다. 실행·모듈 로드 중 `fetch`를 차단하고 시도 횟수를 검사한다. 네이티브 HTTP 라이브러리를 포괄 계측했다는 주장은 하지 않는다.

## 지표를 읽는 법

- **Recall@5**: 관련 ID가 있는 질문마다 `상위 5개에서 찾은 정답 ID 수 / 정답 ID 수`를 계산한 평균이다. 관련 문서가 없는 질문은 이 분모에서 제외한다.
- **MRR@5**: 첫 관련 결과 순위의 역수 평균이다. 5개 안에 없으면 0이다. 중복 결과는 정답 수나 순위를 부풀리지 않는다.
- **no-match false-positive rate**: 관련 문서 없음 라벨의 질문 중 하나라도 결과가 나온 질문의 비율이다. 생성 답변의 환각률과 다르다.
- **exclusion violations**: 명시적으로 제외한 타지역·만료·잘못된 출처 ID가 결과에 나온 질문 수다.
- **통계 의도**: TP/FP/TN/FN, 정확도, 정밀도, 재현율을 따로 표시한다.
- **인용 경계**: ID·URL·숫자에 대한 기계적 검사 통과 수다. 문장 전체의 의미적 근거성은 채점하지 않는다.

고정 지식의 비교 기준은 `scripts/evaluate-rag.mjs`에 동결한 변경 전 substring 검색 알고리즘이다. 개선 검색과 **같은 현재 지식 코퍼스**를 사용한다. 알고리즘 비교이지 과거 배포 전체를 재생한 결과가 아니다. 데이터셋 원시 바이트와 지식 코퍼스 SHA-256을 결과에 기록한다. 공개자료 경로에는 임의의 과거 알고리즘을 만들어 비교하지 않고 현재 경로 진단만 제공한다.

## 선택 사항: 실제 모델의 저장 응답 진단

모델을 자동 호출하지 않는다. 별도로 생성한 **합성 질문의 실제 모델 응답**이 있다면 명시적으로 파일을 전달할 수 있다.

```sh
node scripts/evaluate-rag.mjs --responses saved-model-responses.json --json
```

입력 예시:

```json
{
  "schemaVersion": "bora-rag-saved-responses/v1",
  "responses": [
    {
      "caseId": "audit-emergency-explicit",
      "visibleSourceIds": ["phishing-emergency-response"],
      "answer": "송금과 인증정보 공유를 중단하고 금융회사와 경찰의 공식 채널로 연락하세요. [phishing-emergency-response]"
    }
  ]
}
```

`caseId`는 지식·후속 질문·공개자료 질문 중 하나여야 한다. `visibleSourceIds`에는 실제 모델 입력에 넣은 자료 ID만 기록하며, 이번 실행의 검색 결과에 없는 ID는 거부한다. 검색은 됐지만 입력 길이 제한으로 빠진 문서를 근거로 인정하지 않기 위한 경계다. 중복 ID와 임의 `sources` 본문도 거부한다. 근거 내용은 파일 작성자가 제출한 문자열이 아니라 **이 실행의 실제 검색 결과**에서 가져온다. 따라서 모델 생성 당시와 같은 데이터셋·검색기·코퍼스·발췌를 사용해야 비교가 유효하다. 응답 작성 주체와 입력 자료 ID의 자기기술을 독립 검증하지 않으며 입력 예시 자체는 실제 모델 출력이 아니다.

선택 평가도 인용·숫자 경계만 진단한다. 다음은 계속 별도 사람 검토가 필요하다.

- 각 답변 주장이 인용 원문의 의미와 실제로 일치하는지
- 출처 없는 질문에서 적절히 답변을 보류하거나 확인 질문을 했는지
- 숫자가 원문에 있어도 다른 대상·기간·조건의 값으로 잘못 썼는지
- 최신 제도·실제 자격에 맞는지와 사용자에게 도움이 되는지

독립 검증을 하려면 구현 담당자가 보지 않은 질문과 사람이 검토한 근거 문단을 새로 확보하고, 유사 질문 변형이 개발·검증 양쪽에 섞이지 않게 분리해야 한다. 운영 코퍼스의 답변 가능 범위, 지연시간, 메모리, 실제 모델 답변 품질은 이 진단셋 결과와 구분해 보고한다.
