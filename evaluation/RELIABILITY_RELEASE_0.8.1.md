# BORA Bridge 0.8.1 — 정책 날짜·페이지 상태·모바일 안내 개선

운영 반영: 2026-09-01 00:46 KST, 대표 도메인 https://borabridge.com/.
기존 0.8.0 RAG 작업과 원격 서버의 미커밋 변경을 보존한 추가 패치다.
이 작업에서는 Git 커밋·푸시·master 병합을 하지 않았다.

## 반영 내용

- 온통청년의 `0` 날짜를 2000년 날짜로 해석하지 않도록 공통 날짜 검증을 적용했다. 목록과 RAG가 같은 마감 판정을 사용한다.
- 신청 시작일·마감일·기간 미확인을 구분한다. 날짜가 없으면 신청 가능하다고 단정하지 않고 원문 확인을 안내한다. 정상적인 과거 공고 날짜는 보존한다.
- 긴 정책 설명에도 신청기간 문구가 잘리지 않도록 설명 길이를 배분했다.
- 금융정보 바깥 페이지를 이동한 뒤 돌아와도 비교 조건·계산 입력·비교 결과·안쪽 목록 및 추천 페이지가 유지된다. 이 보존은 현재 페이지의 메모리 안에서만 이뤄지며 금융 입력을 별도로 저장하지 않는다.
- 모바일 보리 말풍선의 가로 넘침을 제거했다. 환율 페이지는 작은 접힌 안내 버튼으로 시작하며, 다음 추천·접기·접은 뒤 키보드 초점 복귀를 유지한다.
- 내용이 바뀌지 않은 공개 자료는 검색 문서를 삭제·재삽입하지 않는다. 갱신 시각만 바뀌면 전문검색(FTS) 텍스트 인덱스를 다시 쓰지 않고, 삭제·이동·중복 문서의 소속은 별도 인덱스로 정확히 추적한다.
- 읽기 전용 운영 점검 도구는 파일 감시를 비활성화했다. 운영 백업 폴더까지 감시해 파일 감시 한도를 소모하던 점검 도구의 문제를 제거했다. 웹 서비스에 포함되는 기능이 아니므로 이 후속 보완에는 서비스 재시작이 필요하지 않았다.

## 공개 자료 보정 결과

| 항목 | 결과 |
| --- | ---: |
| 검색 인덱스 문서 | 30,419건 유지 |
| 온통청년 정책 | 2,749건 유지 |
| 잘못된 2000년 만료일 | 1,307건 → 0건 |
| 신청 마감일 미확인 | 1,307건, 날짜 추정 없이 표시 |
| 명시된 신청 시작일 | 1,442건 |
| 같은 보정 재실행 시 변경 | 0건 |

기본 보정은 `신청기간 0 ~ 0`이라는 원본 표식이 있는 항목으로 한정했다.
옛 900자 제한으로 그 표식까지 잘린 1건은 공식 온통청년 포털에서 시작·종료 값 모두 `0`임을 확인했다.
이 예외는 정확한 자료 ID·공식 출처 URL·기존 날짜·기존 설명의 SHA-256이 모두 일치할 때만 처리한다.
전체 공개 목록, 청년정책 복사본, 공개 스냅샷, 수집 페이지 복사본을 함께 보정했다.

## 검증

- 운영과 분리한 Linux 폴더에서 실제 빌드 성공.
- 전체 Node 자동 테스트 608개 통과, 실패·건너뜀 0개 (약 93.9초, CPU·메모리 제한 사용).
- 별도 공개 자료 리허설: 4개 공개 테이블의 항목 복사본 70,293개를 읽기 전용으로 복사한 뒤, 복사본에서 마이그레이션·날짜 보정·FTS 정합성·문서/청크 소속 일치·재실행 무변경 확인. 계정·세션·개인 금융정보는 이 리허설에 복사하지 않았다.
- 실제 브라우저에서 금융 입력 `1,000,000원 / 12개월`, 월 소득 합성값 `3,000,000원`을 입력했다. 바깥 1→2→1페이지 이동 뒤 값, 비교 결과, 추천 2/8페이지, 상품 목록 2/17페이지가 유지됐다.
- 모바일 320px·375px에서 안내창 가로 넘침 없음, 다음 추천·접기·초점 복귀 확인. 환율 1년 244개 관측일 및 양방향 계산 유지.
- 정책의 기간 미확인/기재된 기간 내 표시, 부산 지역 필터, 새로고침 없는 홈 이동, 로그인 선택창 표시 확인. 점검한 화면에서 브라우저 오류·경고 로그 없음.
- 외부 HTTPS 상태 응답 정상. 웹·LLM 게이트웨이·Ollama·터널 및 기존 복구/수집 타이머 정상.
- 운영 데이터에 대한 제한된 검색 4건 모두 `ready`, 각 4개 근거 반환. 관측 시간 10–39ms는 검색 함수만의 소규모 확인이며 전체 AI 응답 속도나 정확도 향상률을 뜻하지 않는다.

합성 1,000개 자료를 3번 메타데이터 갱신한 검증에서 FTS 논리 SQL 실행 횟수는 6,000→0이었다.
모든 자료의 본문을 교체하거나 순서를 바꾸는 경우에는 이런 감소가 적용되지 않으며, 소속 인덱스 유지 비용이 추가된다.
이를 실제 디스크 쓰기 횟수·메모리 누수 해결률·전체 검색 속도 향상률로 해석하면 안 된다.

## 운영 안전성과 남은 한계

- 배포 직전 원본 파일 지문·Git 상태를 확인했으며, 비공개 DB·코드 백업 후 적용했다. 백업은 프로젝트의 `.deploy-backups/rag-evidence.TJYUjRLD`에 보존했다.
- 실패 복구는 코드와 빌드를 복구하도록 구성했다. 배포 후 들어온 사용자 데이터가 사라지지 않도록 DB 전체를 과거 백업으로 덮어쓰는 자동 복구는 하지 않는다.
- 배포 후 관측한 웹 서비스 메모리는 약 643MiB였다. 재시작 직후의 값이므로 장기 메모리 증가 문제가 완전히 해결됐다는 증거가 아니다. 기존 메모리 경고·자동 복구·상한은 유지했다.
- 고용24는 기존 운영 설정에서 비활성화되어 있고 사용 가능한 인증정보가 없어 그대로 유지했다. 이용 승인 및 사용 가능한 키 확인 후 별도 활성화가 필요하다.
- 금융회사·창업 공고의 저장 상한과 DART의 진행 중인 초기 수집 상태를 정상 완료로 위장하지 않았다. 대규모 수집 확대는 메모리 내 전체 목록 처리와 저장/조회 구조를 먼저 분리한 뒤 진행해야 한다.
- 실제 카카오·네이버 로그인 완료, 개인 장부 저장, 로그인 후 AI 대화 전체 흐름은 이번 브라우저 검증 범위에 포함하지 않았다.
