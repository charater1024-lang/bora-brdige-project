# BORA Bridge 운영 기능 점검 — 2026-09-01

점검 대상: 현재 서비스 중인 [borabridge.com](https://borabridge.com) 및 원격 서버의 실제 배포 코드·캐시·서비스 로그.

점검 시간: 2026-09-01 01:19–01:50 KST. GitHub 구버전의 정적 검토가 아니라, 로그인/비로그인 브라우저에서 운영 기능을 실행한 결과를 우선했다.

## 결론

서버 프로세스는 안정적으로 실행 중이지만, 사이트의 모든 기능이 정상인 상태는 아니다. 특히 공용 법령 AI 요약의 잘못된 내용, 전국 점포 검색 실패, 로그인 홈의 잘못된 데이터 건수, 닫은 로그인 창의 재등장이 재현됐다. AI 상담은 응답하지만 질문 의도와 다른 답변도 생성한다.

이 보고서 외에 앱 코드·환경설정·서비스는 변경하지 않았고 Git 커밋·푸시도 하지 않았다. 실제 UI 시험에 따라 기존 앱이 운영 통계·캐시를 갱신할 수 있으며, **이번 점검 중 예금자보호법의 새 공용 AI 요약이 생성된 것을 화면에서 확인했다. 그 요약에 아래 오류가 있다.** 사용자 자산·프로필·개인화 동의는 저장·삭제·변경하지 않았다.

## 우선순위별 확인된 문제

### P1-01. 잘못된 법령 요약이 공용으로 저장·재사용됨

- 재현: 로그인 → 안심 → 금융 법령 안심 가이드 → 예금자보호 → AI 요약 펼치기.
- 화면은 `새로 생성된 요약 · 모든 사용자에게 공통으로 재사용`이라고 표시했다.
- 요약은 보험료를 잔액의 **5%**로 설명했다. 같은 화면의 공식 제30조는 대통령령으로 정하는 비율의 상한을 **1천분의 5, 즉 0.5%**로 규정한다. 숫자가 10배 다르며, 상한과 실제 적용 비율도 혼동했다.
- 제31조 요약은 보험금을 부보금융회사에 지급한다고 설명했다. 공식 조문은 해당 금융회사의 예금자 등의 청구에 의한 보험금 지급을 규정한다. 지급 대상 설명도 잘못됐다.
- 공식 대조 근거: [국가법령정보센터 제30조](https://www.law.go.kr/LSW/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900324165), [제31조](https://www.law.go.kr/LSW/lsSideInfoP.do?docCls=jo&joBrNo=00&joNo=0031&lsiSeq=277269&urlMode=lsScJoRltInfoR).

배포 코드 원인:

- `app/api/legal/financial/summary/route.ts:49` — 출력 정리는 HTML/Markdown 제거와 길이 제한 위주다.
- 같은 파일 `:249` — 수치·주체·의미 검증 없이 생성된 요약을 저장한다. 일반 AI 상담의 근거 검증 경로와 다르다.
- 같은 파일 `:133` — 준비된 공용 캐시는 로그인 확인보다 먼저 반환한다.
- `lib/legal/financial-law-summary-cache.ts:120` — 설정된 모델명·언어·프롬프트 버전·원문 지문 등이 캐시 식별자다. 같은 모델명 뒤의 실제 모델이 바뀌는 경우까지 보장하지 않는다.
- 같은 파일 `:149` — 준비된 요약 자체에 TTL 검사가 없다. 원문을 다시 조회해도 원문 지문이 같으면 잘못된 요약이 계속 재사용될 수 있다.

권장: 잘못된 공용 요약의 노출을 먼저 중단하고 공식 원문 발췌로 대체한다. 캐시만 삭제하면 같은 검증 없는 경로로 재생성될 수 있으므로, 검증 상태·요약 버전·수치 및 주체 대조를 함께 개선해야 한다. 이번 점검에서는 삭제하거나 설정을 끄지 않았다. 이 결함이 최근 업데이트에서 처음 생겼다고 단정할 근거는 없다.

- 자동 자료 수집과 서울 상권 분석이 이 오류로 실패한다는 근거는 없다.

권장: 날짜 계약을 통일하고 업종/지역/점포의 실제 요청 경로 회귀 테스트 및 비밀정보 없는 오류 기록을 추가한다. **이번 장애 원인은 새 키 발급이 아니라 코드 오류다.** 다만 수정 후 제공기관의 키 인증·이용 승인 성공 여부는 별도로 검증해야 한다.

### P2-03. AI 상담이 질문과 관련된 자료를 찾고도 의도에 맞지 않는 답변을 생성

실제 로그인 상태에서 개인정보 활용 옵션을 모두 끈 채 일반 질문 4개를 보냈다.

| 질문 | 운영 UI 결과 |
|---|---|
| 현재 원달러 환율·기준일·출처 | AI 설명 검증 실패 안내 후 공식 자료 발췌로 대체. 환율 1,376.5 및 기준일 2026-08-31은 자료와 일치 |
| 예금과 적금의 차이를 초보자에게 설명 | 상품 3개의 신청기간이 미확인이라는 답변만 생성. 예금·적금 차이는 설명하지 않음 |
| 청년 월세 지원 신청 전 확인할 조건 | 지역별 정책 3건의 연령·지역·기간을 출처와 함께 제시. 월세 지급 지원 외 임대차 계약 지원도 포함 |
| 학자금대출 금리를 확인할 공식 자료 | 지역별 학자금 이자·원금 지원 공고 4개 중심으로 답변. 중앙 학자금대출 금리 확인 경로 안내는 부족 |

배포 코드 확인:

- `lib/rag/public-catalog.ts`는 예금·적금 키워드를 금융상품 검색으로 연결한다. 개념 설명 의도 분리가 없다.
- 상품 발췌에는 신청기간 미확인 문구가 먼저 붙는다.
- `lib/rag/context.ts:84`의 자료 수·길이 제한에서 공개 상품 자료가 개념 자료보다 먼저 들어갈 수 있다.
- 정적 지식의 상품 비교 자료에는 기본적인 목돈 예치/정기 납입의 차이 설명이 충분하지 않다.
- 기존 검증은 출처·수치 중심이어서 질문에 답하지 않는 문제를 충분히 잡지 못한다.

네 번째 질문의 실제 화면 완료 시간은 약 3.7초였다. 나머지 질문은 완료 시각을 정밀 측정하지 않아 속도 평균을 계산하지 않았다. 별도 로컬 모델 진단 1회에서는 환율 답변이 약 0.8초에 생성되고 근거 검증도 통과했다. 따라서 첫 환율 질문의 실패를 항상 재현되는 모델 장애로 단정할 수 없다. 당시 버려진 원출력이 없어 정확한 검증 실패 사유는 확정하지 못했다. 이 소수 시험으로 정확도 개선율을 산출할 수는 없다.

권장: 질문 의도별 검색 범위, 개념 설명 자료, 관련성 재평가, 안전한 답변 대체 안내를 개선한다. 법령 요약의 검증 문제와 일반 상담의 문제를 별도 경로로 다뤄야 한다.

### P2-04. 창업 지도는 전체 공고가 아니라 첫 페이지 24건만 탐색

- 전체 활성 검색 결과 407건인데 지도는 현재 페이지 24건만 집계했다.
- 첫 페이지 지도에서 부산 0건을 선택하면 0건이 표시됐다.
- 다음 페이지로 가면 지도·상권 위젯 없이 추가 공고 목록만 나타났다.
- 현재 페이지 집계라는 안내는 있으므로 숫자 자체의 숨겨진 오표기는 아니다. 그러나 지역을 먼저 선택해 전체 공고를 찾는 흐름은 제공하지 못한다.

권장: 청년정책과 같이 전체 검색 결과 기반 지역 집계와 서버측 지역 필터를 사용하고, 지역 선택 상태를 페이지 이동 시 유지한다.

### P2-05. 청년정책 개인화 OFF가 ‘수집된 데이터 없음’으로 표시

- 로그인 후 개인화 OFF 상태에서는 수집 5,844건을 보유해도 첫 화면에 정책 0건 및 `수집된 데이터 없음`이 나타났다.
- `전체 정책 보기`를 선택하면 결과가 정상적으로 나온다. 부산 취업·전국 공통 제외는 18건, 같은 범위의 만료 정보는 12건으로 동작했다.
- 개인화 OFF의 추천 0건과 실제 수집 없음은 다른 상태다.

권장: 개인화가 꺼져 있으면 전체 보기를 기본으로 하거나, ‘맞춤 추천 미설정’을 표시한다. 데이터 수집 실패로 보이는 표현을 피한다.

### P2-06. 일부 저장된 정책 날짜의 품질 문제

- 공개 정책 `youth-center-1ookaaq`의 저장된 publishedAt이 점검 당시 서버 시각보다 약 2시간 미래였다.
- 카탈로그와 수집 페이지 캐시에 같은 값이 저장되어 있었다. 서버 시간대는 Asia/Seoul이었다.
- 온통청년 어댑터는 수정일을 publishedAt으로도 사용하며, 원래 날짜 필드를 충분히 남기지 않아 이번 표본의 변환 원인을 정확히 복원하지 못했다.
- 최근 수정된 날짜 정규화만으로 기존 캐시가 전부 다시 정규화되지는 않는다. 미래 날짜를 정렬·최근성 판단에서 제외하는 상한 검사도 없다.
