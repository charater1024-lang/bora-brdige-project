# BORA Bridge 0.8.3 운영 적용 및 검증 기록

대상: `https://borabridge.com` 및 원격 운영 서버. 확인일: 2026-09-01 KST.

## 결론

- 실행 중이던 0.8.2 운영 소스를 기준으로 0.8.3을 구성해 원격 서버에 적용했다. GitHub의 이전 소스로 되돌리지 않았다.
- 계정 전환·로그아웃 뒤 늦게 도착한 응답이 다른 사용자의 화면에 남을 수 있는 경계를 막고, 카탈로그 전체 보존·원자적 게시·재부팅 후 사용자 서비스 지속성 검사를 보강했다.
- 최종 격리 Linux 환경에서 기본 452회, RAG 122회, 안정성 52회, 운영 수정 53회 등 총 679회가 통과했다. 실패·취소·건너뜀은 없었다. 격리 빌드도 성공했다.
- 운영 소스와 실행 산출물은 최종 검증 빌드의 지문과 일치하며, 운영 버전은 0.8.3이다.
- Git 커밋·push·master 병합은 이번 작업에서 실행하지 않았다. 현재 로컬 브랜치는 `codex/rag-evidence-v080`, 기준 커밋은 `e4f0500dfc968284417c6080eda1d666e9239f2d`다.

## 계정·개인정보 경계

- 세션, AI 문맥, 자산 장부, 대화 기록, 동의 상태의 지연 응답을 요청을 시작한 사용자와 세대에 결속했다.
- 로그아웃, 계정 전환, AI 401 응답 시 진행 중 요청을 취소하고 화면에 남은 개인 상태를 함께 비운다.
- 취소를 무시하고 늦게 끝나는 응답도 새 사용자 화면에 반영되지 않는 회귀 검사를 포함했다.
- 홈의 사용자 표시와 실제 인증 세션을 하나의 권위 있는 상태로 통일했다.
- 브라우저에서 비로그인 `BORA Member` 버튼을 눌러 카카오·네이버 로그인 선택지가 표시되는 것을 확인했다. 실제 OAuth 완료, 다른 기기의 저장 복원, 계정 삭제는 이번 비로그인 브라우저 점검 범위가 아니다.

## 공개 카탈로그 및 RAG

- DART live 카탈로그: 22,986건. 완료 백필 22,963건과 최신 페이지에서 새로 합쳐진 고유 23건으로 구성된다.
- K-Startup live 카탈로그: 29,956건.
- 금융회사 기본정보: 공식 제공기관 총계 2,315,282건 중 API 페이지 범위에서 2,000행을 받아 1,011개 고유 회사를 저장한다. 상태를 잘못된 로컬 보존 한도 경고에서 `provider_page_window_limit_reached`로 실제 재수집해 정정했다. 당일 사용 40회, 예약 0회, 연속 실패 0회다.
- 전체 live 카탈로그는 65,161행이고 RAG 문서는 63,361건이다. 차이 1,800건은 누락이 아니라 자연어 정책 근거와 분리한 구조화 상권 분석 자료다. 운영 DB에서 서울 압축 상권 1,650건과 전국 상권 150건으로 확인했다.
- DART·K-Startup 새 세대는 별도 staging 후 단일 트랜잭션으로 live 포인터를 바꾼다. 독자는 이전 전체 세대 또는 새 전체 세대만 보며 중간 혼합 상태를 보지 않는다.
- 완료 백필은 제공기관 총계·수집 총계, 1번부터 마지막까지의 연속 페이지, 일반/마지막 페이지의 행 수, 고유 행 수를 모두 통과해야 게시된다.
- 읽기 전용 검색 표본 4개는 모두 `ready`, 각 4개 근거를 반환했다. 서버 검색 단계는 10–49ms였다. 이는 전체 HTTP 응답 시간이나 의미 정확도 개선율이 아니다.
- SQLite `quick_check`는 `ok`, 카탈로그 RAG 투영과 문서 수는 63,361건으로 일치한다.

## 실행 안정성과 외부 접근

- 웹, Ollama, Local LLM gateway, 공개 API proxy, Cloudflare tunnel과 헬스체크·메모리 감시·공개 데이터 갱신 타이머가 모두 `active`·`enabled`였다.
- 사용자 서비스 지속 실행을 위한 linger는 `yes`, 각 핵심 서비스의 자동 재시작 횟수는 0이었다.
- 자동 시작 canary는 최종 확인 시 26회 연속 준비 상태, 최근 재시작 증가 0을 기록했다. 웹 헬스와 선택된 Local LLM의 `ready` 상태까지 확인한다.
- 공개 헬스는 정확히 `{"status":"ok"}`를 반환했다. 최근 30분 핵심 서비스 warning 수는 0이었다.
- HTTP는 HTTPS로 301 전환되고, HTTPS는 HTTP/2 200을 반환했다. HSTS, CSP, `frame-ancestors 'none'`, `X-Frame-Options: DENY`, `nosniff`, Referrer Policy와 카메라·마이크·위치 등을 끈 Permissions Policy를 확인했다.

## 남은 검증 경계

1. 실제 서버 재부팅은 수행하지 않았다. canary의 `reboot_tested`는 `false`다. 설정 지속성·linger·서비스 활성화·반복 준비 상태는 확인했지만 실제 전원 재기동 시험과는 구분한다.
2. 이번 연결 브라우저는 비로그인 상태였다. 카카오·네이버 신규 사용자 OAuth 전체 흐름, 서로 다른 실제 계정 간 격리, 다른 기기에서 자산 저장값 복원, 탈퇴·삭제는 별도 시험 계정으로 확인해야 한다.
3. 고용24는 운영 설정 OFF이며 상태는 `credential-unavailable`이다. 저장 키를 고용24로 보내는 실연결 시험이나 ON 전환은 명시적 승인 없이 수행하지 않았다.
4. Local LLM gateway의 실제 모델 준비 상태와 기존 근거 회귀 검사는 통과했지만, 이번 최종 점검에서 새 사용자 질문을 모델에 보내지는 않았다. 모든 주제·언어의 의미 정확도나 장기간 품질을 보장한다는 뜻이 아니다.
5. 장시간 부하·메모리 누수·다중 사용자 부하·재해 복원 훈련은 수행하지 않았다.
6. 한 카테고리가 100,000건을 넘는 경우 응답은 부분 표시와 전체 건수를 정직하게 알리지만, 현재 부분 미리보기는 최신순이 아니라 청크 순서다. 현재 운영 데이터는 이 경계에 도달하지 않았다.

따라서 이번에 확인된 0.8.3 수정 범위와 공개 화면은 정상이나, 검증하지 않은 실제 계정·외부 승인·장기 운영까지 포괄해 “모든 기능이 항상 정상”이라고 단정하지 않는다.
