# 운영·배포 도구

이 폴더는 Linux 사용자 서비스, 내부 프록시, 상태 점검, 수집 타이머와 배포 보조 도구를 담고 있습니다. **여기 있는 모든 `.sh` 파일을 순서대로 실행하는 설치 방식이 아닙니다.** 날짜별/기능별 일회성 도구는 해당 시점의 전제와 migration을 포함합니다.

## 먼저 읽을 문서

1. [공개 배포 구성](../docs/deployment-public.md): 런타임 경로와 비공개 설정
2. [운영 호환·전환·복구](../docs/public-runtime-parity.md): 검증과 실제 전환의 구분
3. [DB 백업·보호](../db/README.md), [Local LLM](../local-llm-server/README.md)
4. [내부 관측·보안 백업·복구 검증](../docs/operations-recovery.md): 재시작과 진단 분리, 암호화 사본과 복구 범위

## 주요 파일

| 파일 | 목적 |
| --- | --- |
| `verify-public-runtime.py` | 기존 Local-AI 운영 프로필의 읽기 전용 사전 검사 |
| `deployment-paths.sh` | 프로젝트·실행 파일·설정 경로 검증과 유닛 렌더링 |
| `install-user-units.sh --print ...` | 선택한 유닛의 렌더링 결과만 출력; 서비스 설치/재시작 없음 |
| `run-bora-sandbox.sh` | loopback 웹 실행, 쓰기 범위 제한, 호스트 비밀 파일 마스킹 |
| `stop-local-worker.sh` | SQLite 종료를 고려한 웹 worker 정지 |
| `bora-*.service`, `bora-*.timer` | 웹·프록시·LLM·터널·수집·감시 서비스 템플릿 |
| `install-host-security.sh` | 별도 관리자 권한·새 SSH 접속 확인이 필요한 호스트 정책 도구 |

## 전환 원칙

- Git 상태가 운영 파일 상태와 같다고 가정하지 않습니다. 실제 소스·빌드·설정·유닛을 확인합니다.
- 후보 디렉터리에서 먼저 빌드·테스트합니다. 검증 중 운영 의존성 설치나 모델 다운로드를 하지 않습니다.
- API 키·암호화 키·회원 DB·수집 자료·모델은 기존 것을 유지합니다. 샘플 `.env`로 덮어쓰지 않습니다.
- 백업과 독립된 복구 경로를 먼저 확보한 뒤 타이머와 실행 중 수집/감시 작업을 제어합니다.
- 코드와 빌드, 필요한 설정과 서비스 파일을 한 릴리스로 반영합니다. 기존 활성화 상태를 기록하고 복구합니다.
- 내부/외부 health만으로 끝내지 않고 인증·저장 데이터·모델 준비·기능 회귀를 검사합니다. 실패하면 코드·빌드·설정을 복구하되 새 사용자 데이터를 지우지 않습니다.
- 실제 재부팅 검증과 장기 관찰은 별도입니다. transient 복구 타이머를 재부팅에도 남는 영구 장치로 설명하지 않습니다.

운영 비밀번호·SSH 개인키·터널 자격 증명·실제 환경 파일·DB 백업은 Git에 올리지 않습니다. 루트 `.env.example`과 이 폴더의 `*.example`은 설정 이름과 비밀값 없는 예시만 제공합니다.
