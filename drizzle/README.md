# 스키마 변경 이력

이 폴더의 SQL과 `meta`는 데이터베이스 구조 변경 이력입니다. 실제 회원 정보·API 키·운영 DB dump를 두는 곳이 아닙니다.

- 이미 적용된 migration을 수정하거나 재번호화하지 말고 새 변경을 추가합니다.
- 신규 설치와 기존 DB 업그레이드를 구분하고, 현재까지 적용된 상태를 먼저 확인합니다.
- 일부 기능은 호환성을 위해 런타임의 멱등적인 테이블 생성도 사용합니다. SQL 파일이 있다는 이유만으로 운영에 이미 적용됐다고 판단하지 마세요.
- 테이블/컬럼 추가는 이전 코드로 돌아갈 때의 호환성을 함께 검토합니다. 삭제·타입 변환은 별도의 데이터 이전·복구 계획이 필요합니다.

로컬 migration 진입점은 저장소 루트의 `npm run db:migrate:local`입니다. **운영 서버에서 무조건 실행하지 마세요.** 먼저 대상 D1 파일 선택, 적용된 migration, 온라인 백업, 격리 DB 검증을 확인합니다. `db:generate`는 SQL 생성 작업이며 운영 DB 적용을 의미하지 않습니다.

관련 안내: [DB 보호·백업](../db/README.md) · [배포](../deploy/README.md)

## 0028: 조회 계획 개선

`0028_public_query_indexes.sql`은 OAuth 거래 정리의 `consumed_at` 부분 인덱스와 공공 자료의 `(category, chunk_index, source_id)` 정렬 인덱스만 추가합니다. 기존 인덱스·보존기간·행·수집 설정·API 응답은 바꾸지 않습니다. 전체 카탈로그 JSON 파싱을 SQL 행 페이지 조회로 전환하는 변경은 아닙니다.

배포 전 온라인 백업의 격리 복사본에서 migration을 두 번 적용하여 멱등성, 전체 행 보존, 동일 조회 결과와 `EXPLAIN QUERY PLAN`을 확인합니다. 실제 운영 적용은 승인된 별도 전환 절차에서 수행합니다. 이전 앱으로 롤백해도 두 추가 인덱스를 유지할 수 있으며 사용자 DB를 되돌리거나 인덱스를 급히 삭제할 필요는 없습니다. 세션·회원·API 키 값이나 SQL 응답 본문을 측정 로그에 남기지 마세요.
