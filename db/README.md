# 데이터베이스와 사용자 데이터

`index.ts`는 런타임 D1 연결, `schema.ts`는 데이터 구조를 정의합니다. SQL 이력은 [drizzle](../drizzle/README.md), 기능별 조회·변경 정책은 `lib`와 `app/api`에 있습니다. 운영 DB 파일은 이 폴더나 Git에 포함하지 않습니다.

## 저장 범위

- 로그인 계정·세션 해시·필수 약관 동의
- 사용자가 직접 입력한 자산·부채·월 현금흐름과 개인화 설정
- 명시적 동의를 받은 대화·기억·최근 활동
- 공식 API 수집 결과·수집 진행 상태·RAG 색인·요약 캐시
- 관리자 설정·암호화된 API 자격 증명·평가 기록

로그인한 동일 계정의 장부는 서버 DB에 저장되므로 다른 기기에서도 조회할 수 있습니다. 비로그인 기기 내 임시 상태와 구분합니다. 마이데이터나 실제 금융 계좌에서 가져온 값이 아닙니다.

## 보호 범위와 한계

사용자 데이터는 세션의 사용자 ID로 범위를 제한하고 SQL 파라미터 바인딩을 사용합니다. 세션 토큰은 해시 형태로, 저장 API 키는 AES-GCM 암호문으로 보관합니다. `DEVELOPER_SETTINGS_ENCRYPTION_KEY`는 별도 비공개 설정으로 유지해야 합니다.

**API 키 암호화는 DB 전체 암호화를 의미하지 않습니다.** 자산·프로필 등 일반 컬럼은 SQLite 수준에서 자동 암호화되지 않습니다. 디스크 암호화, 전용 서비스 계정, 호스트 관리자 권한과 백업 보안은 별도로 설계·검증해야 합니다.

로컬 운영 프로필은 서버의 비공개 `.wrangler/state` 아래 SQLite 파일을 사용하며 DB 네트워크 포트를 공개할 필요가 없습니다. 다른 사용자 계정이 DB·WAL·SHM·환경 파일을 읽지 못하게 디렉터리 `0700`, 민감 파일 `0600` 등 권한을 확인하세요. Windows에서는 해당 파일의 ACL을 검토합니다.

## 백업·복구

- 운영 중 SQLite 파일 하나만 복사하면 WAL에 있는 최신 변경을 놓칠 수 있습니다. SQLite 온라인 backup API를 사용하고 백업의 `quick_check`/무결성을 확인하세요.
- DB뿐 아니라 API 키 복호화에 필요한 기존 암호화 키도 안전하게 보관합니다. 백업을 공개 소스 ZIP에 넣지 마세요.
- 코드 롤백은 사용자 DB를 과거 시점으로 덮어쓰는 작업이 아닙니다. 전환 이후 저장한 사용자 데이터를 보존합니다.
- 테스트용 조회·저장·삭제는 격리된 복사본 또는 합성 DB에서 수행합니다. 운영 사용자 계정을 테스트 계정처럼 사용하지 않습니다.

배포 전 확인 절차는 [공개 소스/운영 호환 안내](../docs/public-runtime-parity.md)를 참고하세요.
